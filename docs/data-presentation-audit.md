## Preserved protections and contract limitations

- **KYC CPF/CNPJ:** `investor.documentMasked` and `bureau.documentMasked` are explicitly Backend-masked fields. Their existing mask validator remains. No full document is reconstructed, fetched from another domain or invented.
- **Investor 360° document:** `investor.documentMasked` remains a safe Backend mask. Accounts does not expose CPF/CNPJ; those fields remain unavailable there.
- **Entrepreneur 360° Company CNPJ:** recorded live contract evidence states that overview `company.cnpj` is Backend-masked. It remains masked as provided. Full canonical CNPJ is already available on the linked, authorized Company detail; this revision does not add a fetch or silently replace the overview value.
- **Finance unsafe responses:** full/barely masked counterparty CPF/CNPJ, documents in references/descriptions/names, wrong money unit, mismatched scope/identity/owner and conflicting balances still reject the entire response. No security rejection is disabled to display more data.
- **Audit arbitrary metadata:** password/token/key/provider secret, raw banking/card, document/identity/biometric, payload and signature key redaction remains. Backend `[REDACTED]` markers, credential-pattern detection, invalid-object/accessor rejection, depth/node/character budgets and bounded technical-text truncation remain. Full operational emails do not authorize unmasking generic bank/document payloads. A new field-specific contract is needed before expanding these fields.
- **Banking/PAG/SMTP:** private configuration, raw credentials and secrets stay hidden/write-only. Prototype masked hints move with mock-only runtime separation; they are not an operational banking read contract.
- **Navigation/table clipping:** breadcrumb truncation, bounded search parameters, CSS ellipsis (where full text remains in the accessible DOM/detail), Terms previews, CSS/WebGL masks and numeric/date formatting are not confidentiality redaction. They are not replaced indiscriminately.
- No response payload logging, persistence, expanded reads, new dependency, API authorization/session change or financial operation is introduced by these presentation changes.
