## Common contract rules from the original proposal

Existing Nest route prefixes below include `/api`. `:id` is a canonical positive numeric Whitelabel ID. Slug, aliases, host and base URL are identity/consumer-resolution metadata; none may silently substitute for `:id`. Every command must verify tenant ownership before acting. SUPER_ADMIN is the proposed write role; qualified reads retain SUPER_ADMIN/READ_ONLY unless a capability explicitly requires a narrower policy. Other roles fail closed. Existing authentication and Backend RBAC remain authoritative.

Proposals for `baseVersion`, `version`, `If-Match`, draft state, delete/reset, idempotency and new paths are **not implemented contracts**. Backend must choose and publish one consistent concurrency convention. A fresh GET followed by PUT is not atomic conflict protection. Current frontend never automatically retries uncertain mutations; it reconciles through scoped authoritative GET. Safe feedback retains fixed messages, known error codes and UUID references, never arbitrary server text or credential echoes.

Each item below contains the requested 15 handoff fields. Priority P0 means a release/privacy prerequisite; P1 is functional parity; P2 is a separately scoped extension.
