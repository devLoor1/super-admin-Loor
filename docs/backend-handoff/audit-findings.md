## Findings and implications

| ID | Source finding | Handoff implication |
| --- | --- | --- |
| A-01 | Whitelabel registry/resolver and tenant FKs exist; management CRUD/lifecycle API not found. | Reuse identity domain but implement/expose management services. Active resolver filtering is not complete tenant shutdown. |
| A-02 | Core has separate Admin, Investor, Entrepreneur and private-module token guards, not an independent Control Plane operator/service boundary. | New operator auth and internal service authorization are foundation dependencies. |
| A-03 | General account access-state/pause/reactivate and all-session revoke commands were not found. | Implement agreed access policy; do not substitute validation denial, soft-delete or tool disable. |
| A-04 | Admin has nullable single tenant FK plus legacy `isSuperAdmin`; no Admin-management CRUD/invitation flow found. | Tenant Admin management needs explicit provisioning and safe reads. |
| A-05 | Admin Investor/Entrepreneur reads exist with auth-aware scope. Some settings/assets/tools/KYC paths resolve request tenant differently. | Normalize tenant ownership before internal exposure; header filtering is insufficient. No live exploit is claimed. |
| A-06 | Investor account-validation/KYC gates are route-specific. Investor self-delete is soft deletion; Entrepreneur has no matching general delete/pause state. | Preserve distinction among access, verification, validation and deletion. Token/background effects remain unverified. |
| A-07 | Account, Opportunity, Investment/provider/documents and financial relations have independent lineage. Supported reassignment service not found. | Moving a tenant FK alone is not a safe account migration. |
| A-08 | Tenant Terms revisions and registration acceptance exist. Existing-user forced reacceptance/acceptance-history ledger not found. | Expose existing legal domain; define additional acceptance policy separately. |
| A-09 | Questionnaire/profile are global; fixed-ID validator and weighted calculation exist. The save path retains classification, not full answer/version history. | Reads can reuse the domain; editable tenant catalog and governed classification need new semantics. Seed ranges are not final Product approval evidence. |
| A-10 | Selected tenant flags/settings, Admin menu visibility, owner tools and payment-provider mapping exist as distinct capabilities. | Do not call them a unified RBAC/entitlement/plan system. Generic gateway architecture is only partially represented. |
| A-11 | Limited sanitized audit events exist; writer is best effort and there is no general immutable query/audit contract. | Define reliable Control Plane/Core audit responsibilities with correlation. |
| A-12 | Ordinary email/password login is not a tenant/account-active guard. Resolver fallback and actor scope vary by path. | Pause/lifecycle design must cover actual access surfaces; authentication and resolver behavior require focused runtime validation later. |

Current Entrepreneur Admin creation must be read from the audited service, not old homolog QA notes: this source provisions a temporary password result and verified/prefilled state rather than proving the earlier setup-email workflow is the current contract. This is not a recommendation to adopt that provisioning policy for managed tenant Admins.

## Current route families and proposed exposure

Route sources are pinned below. Paths here are logical Core paths, not assumed deployed proxy prefixes.

| Current Core path family | Existing capability | Limit for Super Admin |
| --- | --- | --- |
| `/auth/admin`, `/auth/investor`, `/auth/entrepreneur` | Actor login/logout/recovery/registration as defined per actor | Not independent Control Plane auth or service tokens; Admin registration is dev/test-only |
| `/admin/investors`, pending/denied/detail/portfolio; detail approve/deny | Scoped account reads; manual-validation decisions | No general pause/reassign/global read contract; incomplete detail limitations |
| `/admin/entrepreneurs` and detail/company-information subroutes | Scoped account create/update/read and Company validation | Not pause/reassignment; existing mutations have domain side effects |
| `DELETE /investors` | Authenticated Investor self soft-delete | Not managed pause; no explicit all-session revoke/financial cleanup guarantee |
| `GET /terms-of-use`; `GET/PUT /admin/terms-of-use` | Tenant current legal content and revision publication | Internal/Control Plane exposure missing; reacceptance absent |
| `GET /investors/questions`; `PUT /investors/investor-profile`; `GET /admin/investor-profiles` | Catalog read, calculation, profile summaries | Not management CRUD, per-tenant catalog or threshold governance |
| `/admin/platform`, `/investor/platform`, `/admin/menu-config`, owner tool routes | Settings/defaults, public settings, menu/owner-tool controls | Different scope/semantics; not a unified module entitlement system |
| Admin SMTP/email-template/platform-asset paths | Configuration/content operations with safe metadata and some audit | Reuse only through authorized internal exposure, not direct browser service access |

No `/internal/super-admin/v1` route family was found. The architecture's proposed internal endpoints and scaffold remain **BACKEND IMPLEMENTATION NEEDED**, not delivered endpoints. No live route was called for this documentation task.
